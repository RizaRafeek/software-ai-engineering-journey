    RESTful API :
        if an API follows all the six principles of Rest Architecture



6 guiding principles of REST:
    -client-server architecture:
        client and server must be completely seperated from each other
        They should be able to evolve independently
    -Statelessness:
        Every single request from the client to the server must contain all the information needed to understand
        and fulfill the request
        The server does not store any memory (context) about past requests on its own.
        so even if the past one fails the second can do its job just fine
    -Cacheability:
        The server must explicitly tell the client whether a piece of data can be cached (saved locally) and for how long.
        cacheing helps to load the data faster at lightning speed 
    -Unifform Interface;
        API -look and behave similar so any developer can read and understand them
            -clean, unique url
            -request/response has enough metadata to tell receiver how to process it
            -HATEOS - modern web skips this - server return link in response telling the client what actions it can do next
    -Layered System:
        client cannot tell if it is connected directly to end server or intermediary
    -Code on Demand:
        server can occasionally send executable code ddown to client to run locally
